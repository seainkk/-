## Постоянная страница входа

Основная ссылка команды — `https://seainkk.github.io/-/#access_key=КЛЮЧ`. Публичные файлы страницы лежат в `entry/` и не содержат сам ключ. Google-приложение открывается в `credentialless` iframe без cookies браузерных аккаунтов; его вложенные окна наследуют изоляцию. Нативные Google Таблицы в новых вкладках сохраняют обычные аккаунты браузера. Режим требует актуального Chrome/Edge; неподдерживаемый браузер получает сообщение, а не скрытый переход к обычному iframe.

Владелец репозитория один раз открывает https://github.com/seainkk/-/settings/pages и выбирает **Build and deployment → Source → GitHub Actions**. Первое включение Pages недоступно обычному `GITHUB_TOKEN`: это ограничение configure-pages. Дополнительный персональный токен не нужен. После настройки workflow **Deploy registry entry** публикует `entry/` при изменениях этой папки; при первом отказе настройки повторите workflow после включения Pages. Серверная публикация Apps Script остаётся отдельной и сохраняет прежний Deployment ID.

После публикации проверяют фактический вход через страницу Pages с действующим ключом и отсутствие Google Cookie в запросах credentialless iframe. Сам iframe сообщает готовность только после успешного server-side bootstrap. Прямой анонимный тест `/exec` без cookies не воспроизводит многопользовательский маршрут Google и сам по себе не доказывает удобный вход в обычном браузере.

## Режим развёртывания

В [проекте Apps Script](https://script.google.com/home/projects/1FyQVeeqd4X13NqQ7PtRMVg7U8p60yk-tWvgK-9vmPdpQgK-mQE3sL8aH/edit) существующее веб-приложение должно быть опубликовано так:

- «Выполнять от моего имени» — `USER_DEPLOYING`.
- «Кто имеет доступ: Все», включая пользователей без входа в Google — `ANYONE_ANONYMOUS`.

Путь при ручной настройке: «Развернуть → Управление развертываниями → существующее веб-приложение → карандаш». Сохраните существующий Deployment ID, не создавая новый адрес. Если политика Google Workspace запрещает анонимное открытие, эту политику должен изменить администратор организации; браузерный код её не обходит.

Публичная страница содержит только статический интерфейс. Данные и операции защищены отдельным серверным ключом каждого запроса. Нельзя переносить режим владельца на старую версию без этой проверки. Текущая версия также блокирует импорт по ссылке из-за пределов реестра, чтобы её получатели не могли обращаться к другим файлам владельца.

## Настройки и ключ

`ROOT_FOLDER_ID` задаёт корень; при отсутствии используется подготовленный ID из `Config.gs`. Необязательные привязки: `SOURCE_BASES_FOLDER_ID`, `SOURCE_BASES_STORAGE_ID`, `SEGMENTS_FOLDER_ID`. Папки должны принадлежать реестру; служебная таблица — непосредственно корню. Старые `ALLOWED_EMAILS` и `ADMIN_EMAILS` не применяются; панель команды удалена. Доступ к папке теперь настраивают обычным интерфейсом Google Диска, когда нужно открывать сами таблицы.

Публичный `Config.gs` содержит только SHA-256 verifier случайного 256-битного ключа. Не сохраняйте сырой ключ в исходниках, workflow, переменных CI или публичных логах. Закрытая ссылка передаётся владельцу отдельно.

Для смены ссылки сгенерируйте новый криптографически случайный 32-байтовый ключ в Base64URL без `=`. Вычислите SHA-256 его 43-символьной текстовой формы и закодируйте результат в Base64URL без `=`. Владелец может сохранить полученный verifier в Script Properties под именем `SHARED_ACCESS_KEY_SHA256`. После этого действует новая ссылка; прежний ключ перестаёт проходить проверку. Пустое/неправильное свойство блокирует вход, а не возвращает доступ по прежнему ключу. Само свойство не содержит исходного ключа. Альтернатива — обновление verifier в `Config.gs` и публикация при отсутствии override-свойства.

## GitHub Actions

В `main` сохранён workflow Deploy Apps Script. Его существующий GitHub Secret `CLASPRC_JSON` содержит авторизацию clasp. Содержимое секрета не передаётся в чат. Скрипт создаёт приватный временный файл с правами 0600 и удаляет его при любом завершении.

Каждое обновление выполняет установку зависимостей, статическую проверку, тесты, `clasp push --force`, создание версии и переключение существующего deployment. Затем серверный скрипт читает фактические настройки Google Apps Script API и проверяет проект, версию, неизменный URL, `USER_DEPLOYING` и `ANYONE_ANONYMOUS`. Исходные ответы авторизации скрыты. Если режим Google не совпал, CI сообщает, что публикация ещё не подтверждена, и предлагает изменить существующее развёртывание; молчаливого создания нового URL нет.

Для первой установки или восстановления авторизации нужен Node.js 22+:

```sh
npm ci
npm run configure
npm run check
npm test
npx clasp login
```

Включите Apps Script API на https://script.google.com/home/usersettings. Авторизуйтесь аккаунтом, который должен выполнять операции приложения. Локальный `.clasprc.json` используйте только для закрытого секрета GitHub. При ручной публикации задайте `APPS_SCRIPT_DEPLOYMENT_ID` и выполните `npm run deploy`. Для исправления GitHub-авторизации повторите `clasp login`, замените секрет напрямую в GitHub Settings и запустите Deploy Apps Script ещё раз. Не помещайте файл авторизации в репозиторий.

`npm run configure` меняет только привязку `.clasp.json`. Если нужна первоначальная проверка папки из редактора Apps Script, приватная `setupRegistry_` проверяет корень и verifier; списки email она не создаёт. Дальнейшие изменения кода публикуйте из GitHub: прямые изменения редактора будут заменены следующей загрузкой.

## Google Drive API и служебные данные

Манифест использует V8 и Advanced Drive API v3. Разрешения Drive, Sheets и `script.external_request` остаются у опубликовавшего аккаунта; посетителям не передаются OAuth-токены. Если привязан стандартный Google Cloud-проект, включите Google Drive API в нём. Для автоматически созданного проекта Apps Script API подключается вместе с advanced service.

Прежний служебный реестр обновляется приложением без сброса ручных статусов, версий и связей. Неподтверждённые импорты/копирования имеют журнал восстановления, который нельзя очищать до проверки результата. Записи новых действий используют общий актор `shared-link`; по нему нельзя установить конкретного сотрудника.

Файловый импорт ограничен 10 МиБ и нативным Blob HTML Service. Для импорта по Google-ссылке источник должен находиться внутри корня реестра; для переноса — в исходной папке или её подпапке. Владельцы с нужными Google-правами могут заранее положить внешнюю базу в «Исходные базы». Приложение не меняет публичность папок или таблиц и не выдаёт автоматически права на Диске получателям закрытой ссылки.

## Проверка результата

Сначала убедитесь, что шаг Update existing web app завершился успешно и фактическая конфигурация подтверждена. Затем проверьте реальную страницу без Google-сессии: обычный адрес без ключа даёт только экран закрытой ссылки; полный адрес с действующим ключом открывает интерфейс; неверный ключ не вызывает обращения к данным. Убедитесь, что `google.script.url.getLocation` получает фрагмент родительского URL. Проверки с макетами не доказывают реальную маршрутизацию Google или права опубликовавшего аккаунта.

Все посетители с действующим ключом могут пользоваться одинаковыми рабочими функциями и пересылать ссылку. Для открытия нативной Google Таблицы сотрудник отдельно использует аккаунт с правами на файл. API Coldy/NSA, проверка запусков и структура ретаргетинга остаются отдельными будущими задачами.

Официальные источники: [Web apps](https://developers.google.com/apps-script/guides/web), [HTML Service URL](https://developers.google.com/apps-script/guides/html/reference/url), [Session](https://developers.google.com/apps-script/reference/base/session), [deployments API](https://developers.google.com/apps-script/api/reference/rest/v1/projects.deployments/get).
