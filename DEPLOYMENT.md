# Публикация реестра баз

Код хранится в GitHub, интерфейс и серверные функции работают в Google Apps Script, таблицы — в выбранной папке Google Диска. Google Sites для запуска не требуется. Рабочая ссылка одна для всей команды; при обновлении сохраняется.

Подготовленная привязка:

- проект Apps Script: `1FyQVeeqd4X13NqQ7PtRMVg7U8p60yk-tWvgK-9vmPdpQgK-mQE3sL8aH`;
- исходники Apps Script: `src`, отображение проекта: `.clasp.json`;
- папка баз: `1WKcvDDKqYBo94eXsYc5vKp6OPtOzv6Wh`.

Постоянный адрес приложения: <https://script.google.com/macros/s/AKfycbxKxdFPQt4gGQAOrgyRUBNm1yQEhEyEeXTiPPZqYz2KsVEZNyD6gXrDRj78BhgybCv0WA/exec>. Его Deployment ID уже задан в workflow. Создавать новое развёртывание при каждом обновлении не требуется.

В текущем публичном репозитории допустимы эти идентификаторы, исходный код и ссылки. Пароли, OAuth-токены и `.clasprc.json` в репозиторий и чат не помещаются. Авторизацию выполняет владелец Google-проекта на своём компьютере.

## 1. Один раз загрузите код

Установите [Node.js](https://nodejs.org/) 22 или новее. Откройте репозиторий GitHub, нажмите **Code → Download ZIP** и распакуйте его на своём компьютере. Откройте терминал в распакованной папке, где находится `package.json`, и выполните:

```sh
npm ci
npm run configure
npm run check
npm test
```

Включите **Google Apps Script API** на странице <https://script.google.com/home/usersettings>. Затем выполните:

```sh
npx clasp login
npm run push
```

В открывшемся браузере войдите в Google-аккаунт владельца проекта и разрешите доступ. `clasp login` создаёт локальный файл `.clasprc.json` в домашней папке. Его содержимое используется только для секрета CI на следующем этапе. `npm run push` загружает текущие файлы в Apps Script; он ещё не публикует рабочее приложение.

## 2. Настройте команду и создайте первую рабочую ссылку

1. Откройте свой [проект Apps Script](https://script.google.com/home/projects/1FyQVeeqd4X13NqQ7PtRMVg7U8p60yk-tWvgK-9vmPdpQgK-mQE3sL8aH/edit).
2. Откройте слева **Project Settings → Script properties → Add script property**. Добавьте три пары ключ/значение: `ROOT_FOLDER_ID` = `1WKcvDDKqYBo94eXsYc5vKp6OPtOzv6Wh`; `ALLOWED_EMAILS` = ваш Google-email; `ADMIN_EMAILS` = тот же Google-email. Нажмите **Save script properties**. Email вводится без кавычек. Выполнять функцию `setupRegistry_` для этой настройки не требуется.
3. После первой настройки добавляйте сотрудников через кнопку «Доступ команды» в приложении под аккаунтом администратора. Укажите Google-email и роль: «Сотрудник» для всех рабочих операций, «Администратор» дополнительно для управления доступом. Сервер выдаёт редакторские права на корневую папку и проверяет их перед добавлением адреса в `ALLOWED_EMAILS`; роль администратора также добавляет адрес в `ADMIN_EMAILS`. Старые участники сохраняются. Для ручной настройки по-прежнему можно дописать адреса в Script Properties через запятую и отдельно выдать права на Диске.
4. Выберите **Deploy → New deployment → Web app**. Для **Execute as** укажите **User accessing the web app**. Для доступа выбирайте вошедших Google-пользователей либо свой Workspace-домен, если этот вариант доступен. Анонимный доступ не включайте. Сервер приложения дополнительно проверяет список команды.
5. Сохраните **Web app URL**, оканчивающийся на `/exec`, и **Deployment ID**. Команде отправляйте `/exec`, а не тестовую ссылку `/dev`.
6. Откройте приложение под своим аккаунтом, затем под аккаунтом одного участника. При первом входе каждый участник подтверждает нужные разрешения. Внешние Gmail-аккаунты могут видеть предупреждение непроверенного OAuth-приложения; ограничения зависят от настроек проекта и аудитории.

Приложение запрашивает широкие разрешения Google Drive/Sheets. Ограничение выбранной папкой обеспечивается серверными проверками приложения; само OAuth-разрешение не ограничено этой папкой.

## 3. Включите автоматическую публикацию из GitHub

В репозитории откройте **Settings → Secrets and variables → Actions**:

| Раздел | Имя | Значение |
| --- | --- | --- |
| Secrets | `CLASPRC_JSON` | Всё содержимое локального файла `.clasprc.json`, созданного `clasp login`. Введите непосредственно в поле GitHub Secret. |

ID текущего развёртывания уже настроен в `.github/workflows/deploy.yml`. Если впоследствии понадобится другой адрес приложения, можно добавить **Variables → `APPS_SCRIPT_DEPLOYMENT_ID`** с новым ID. Это необязательная настройка для текущего приложения.

На Windows файл авторизации можно открыть из той же командной строки, где выполнялся `npx clasp login`:

```bat
notepad "%USERPROFILE%\.clasprc.json"
```

Содержимое вводится непосредственно в **GitHub → New repository secret → `CLASPRC_JSON`**. Если Блокнот предлагает создать новый пустой файл, отмените действие и проверьте, под каким пользователем компьютера выполнялся вход `clasp login`. В чат файл авторизации не передаётся.

Другие секреты, ключ сервисного аккаунта и данные входа участников для этой схемы не нужны. `.clasp.json` уже содержит привязку проекта и безопасен для исходников. Доступ к изменению workflow и ветки `main` следует выдавать людям, которым доверена публикация приложения от имени владельца.

После настройки откройте **Actions → Deploy Apps Script → Run workflow**. В дальнейшем публикация запускается после изменений в `main`: сначала проверки и тесты, затем загрузка исходников, создание версии и переключение **существующего** deployment на эту версию. Входной URL остаётся прежним. Уже открытым страницам требуется обновление.

До заполнения секрета workflow выполняет проверки, выводит уведомление `Publication skipped` и ничего в Google не публикует. Добавление секрета само по себе не запускает публикацию: после сохранения нажмите **Actions → Deploy Apps Script → Run workflow** один раз. Это ожидаемый порядок первого подключения CI.

## Ручное обновление и устранение ошибок

Для локальной публикации после `clasp login` задайте переменную окружения `APPS_SCRIPT_DEPLOYMENT_ID` с существующим ID и выполните `npm run deploy`. Скрипт откажется запускаться без этого ID и не создаёт новое развёртывание.

Если GitHub сообщает об ошибке авторизации, повторите `npx clasp login` локально и замените секрет `CLASPRC_JSON`. При изменении набора разрешений может потребоваться повторное согласие Google. Секреты в логи публикации не выводятся; временный файл авторизации удаляется после выполнения, включая ошибочные завершения.

После подключения CI редактируйте код в GitHub/локальной копии и публикуйте через него: прямые изменения в редакторе Apps Script будут заменены следующей загрузкой из `main`.

## Google Drive API для загрузки баз

В манифесте приложения подключён Advanced Drive API v3. Он преобразует загруженный файл в Google Таблицу, создаёт копии таблиц в папке исходных баз и создаёт папки и два файла нового сегмента с метками восстановления. Google Таблицы, добавленные по ссылке, доступны только с правами вошедшего сотрудника; принадлежность папки назначения и служебной таблицы реестру проверяет приложение.

Если Apps Script использует автоматически созданный Cloud-проект, Google включает API при подключении advanced service. Если владелец привязал стандартный Google Cloud-проект, в нём нужно один раз открыть **APIs & Services → Library → Google Drive API → Enable**. Сам факт публикации кода ещё не подтверждает, что API включён в отдельно настроенном Cloud-проекте. При соответствующей ошибке загрузки проверяется именно проект, связанный с Apps Script, а не произвольный проект Google Cloud.

После добавления разрешения `script.external_request` Google может запросить повторное согласие пользователей. Это разрешение используется только сервером для фиксированных Google Drive API endpoint при ссылках с resource key. OAuth-токены не передаются в интерфейс и не выводятся в сообщения об ошибках.

Файлы принимаются формой HTML Service: форма — единственный аргумент `google.script.run`, а file input поступает на сервер как Blob. Ограничение 10 МиБ установлено приложением. Преобразование выполняет Google, без собственного редактора ячеек. В режиме копирования оригинал остаётся на месте; в режиме переноса исходная таблица перемещается и переименовывается.

Автоматические тесты импорта подменяют Google API. Первую реальную загрузку файла, копирование и перенос нужно проверить под разрешённым Google-аккаунтом после публикации; проверки с макетами не заменяют эту проверку прав и настроек Cloud-проекта.

Официальные инструкции: [clasp и GitHub Actions](https://developers.google.com/apps-script/guides/clasp), [версии и постоянный URL](https://developers.google.com/apps-script/concepts/deployments), [права web app](https://developers.google.com/apps-script/guides/web), [Advanced Drive](https://developers.google.com/apps-script/advanced/drive), [включение advanced services](https://developers.google.com/apps-script/guides/services/advanced), [форма с Blob](https://developers.google.com/apps-script/guides/html/communication).

## Обновление реестра и сегментов

Текущий интерфейс содержит «Реестр баз», «Сегменты» и «Ретаргетинг». Отдельный экран дерева Диска удалён; физические папки «Исходные базы» и «Аутричи» не переименовываются. Наполнение базы теперь допускает «Компании» и «ЛПР» одновременно.

При первом открытии каталога прежние 11 или 12 столбцов `SourceBases` автоматически дополняются до 13; прежние статусы, проверки, версии и связи сохраняются. При первом создании или изменении сегмента приложение добавляет служебные листы `SegmentTables` и `SegmentLoads`. Не создавайте их вручную и не удаляйте журнал незавершённой загрузки: он предотвращает повторное копирование листов. Миграция и запись выполняются под общей блокировкой Apps Script.

Новые разрешения по сравнению с версией импорта не требуются. Для создания сегмента сотруднику нужны права на создание папок и файлов внутри «Аутричи», для загрузки листов — доступ к исходной Google Таблице, редакторские права на файлы сегмента и служебную таблицу. Исходная база должна иметь сохранённый статус «Готова».

После публикации обновите открытую страницу и проверьте под разрешённым аккаунтом: создание пустого сегмента с двумя файлами, добавление готовой базы с выбором листов и заголовков, запрет неготовой базы, переименование сегмента. Автоматические тесты используют макеты Google API; реальные контакты в рабочие файлы при проверках разработки не добавляются.

Coldy и NSA пока показывают экран без подключения API; запуск каналов, показатели в работе и наполнение ретаргетинга будут определены отдельно. У старого листа с единственной заполненной строкой без сохранённой настройки заголовка статус может быть неопределённым: приложение не принимает возможный контакт за заголовок автоматически.

## Если не удаётся перенести таблицу

Приложение выполняет действие от имени аккаунта, указанного в его шапке. Права подключённого к чату аккаунта и аккаунта приложения могут отличаться. Редактор Google Таблицы не всегда вправе переносить её между папками или дисками. Сначала проверьте, что выбран нужный аккаунт, исходная таблица доступна, а в папку «Исходные базы» можно добавлять файлы.

Перед новым действием приложение проверяет явные запреты Google на копирование, переименование, перенос и добавление в папку. Отсутствующий признак прав не считается запретом; положительная проверка не отменяет ограничения Google на конкретную пару папок. Уже подтверждённый результат и повторное восстановление не требуют создавать ещё одну копию.

Если Google запрещает перенос чужой таблицы, выберите «Создать копию», когда владелец разрешил копирование, либо попросите владельца выполнить перенос. Приложение самостоятельно не меняет режим импорта и не меняет права доступа. Ошибки исходника, папки назначения, копирования, переноса, ограничений запросов и свободного места различаются в сообщении; исходные ответы Google с частными данными в браузер не передаются.

## Добавление второго аккаунта из приложения

Откройте опубликованное приложение из уже разрешённого аккаунта администратора. Нажмите «Доступ команды», введите второй Google-email, выберите «Администратор» и отправьте форму. Дождитесь подтверждения. Затем откройте ту же ссылку приложения во втором аккаунте, например в отдельном профиле браузера, и подтвердите разрешения Google. Для обычного сотрудника достаточно роли «Сотрудник»: все операции с базами и сегментами ей доступны.

Для выдачи доступа текущий аккаунт должен иметь право делиться корневой папкой; сам флаг администратора приложения не расширяет права Google. Права выдаются конкретному пользователю, без публичных или доменных разрешений и без письма-уведомления. Уже существующие более сильные права на Диске сохраняются. Повтор с тем же email проверяет уже выданный доступ; неизвестный результат выдачи прав не вызывает слепого повторного приглашения.

Если права на папку выданы, но сохранение допуска в приложение не подтвердилось, повторите ту же форму с тем же email и ролью. Вход ещё не подтверждён до успешного завершения. Не очищайте вручную журнал незавершённой выдачи доступа. Отдельные ограничения Google на внешние таблицы, перенос чужих файлов или папки с ограниченным наследованием требуют соответствующих прав на сами эти объекты.
