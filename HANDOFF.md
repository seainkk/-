# Передача проекта в Codex

Актуально на 19 ноября 2026 года. Основная ветка — `main` в https://github.com/seainkk/- . Текущий код уже опубликован; развёртывание обновляется через GitHub Actions.

## Что это за приложение

«Реестр баз» — командный сервис для подготовки баз компаний и ЛПР к email- и Telegram-аутричу. Интерфейс работает с настоящими Google Таблицами. Постоянно включённый компьютер и отдельный сервер не требуются.

- Входная страница: https://seainkk.github.io/-/ . Для рабочих операций нужна выданная владельцем закрытая ссылка с ключом во фрагменте. Сам ключ в репозитории отсутствует.
- Приложение и сервер: Google Apps Script, выполнение от владельца проекта. Клиент вызывает фиксированный dispatcher `callApp`; загрузка файла использует `uploadSourceBase`.
- Google Диск хранит исходники, рабочие файлы сегментов и служебные журналы. GitHub хранит исходный код, инструкции и workflow публикации.

## Реализовано

1. Разделы реестра «Компании» и «ЛПР», поиск и фильтры; статусы «Сбор», «Готова», «Доработка».
2. Импорт файла или таблицы через предпросмотр. Создаётся отдельная Google Таблица: все исходные листы плюс Email и телефоны/Telegram без дублей. При одном исходном листе получается три вкладки. Формулы исходника фиксируются значениями; исходный файл сохраняется.
3. Извлечение контактов по содержимому ячеек и ссылок, в том числе из разных исходных листов. Явные названия «ЛПР»/«Компании» помогают распределению; явный выбор пользователя имеет приоритет. Спорная принадлежность контактов показывается для проверки.
4. Редактор таблицы в сервисе с сохранением в Google Sheets, контролем конфликтов, клавиатурой и вставкой диапазонов.
5. Пополнение двух нормализованных файлов сегмента — компании и связанная ЛПР-база. Принимаются только готовые исходники. Повторные загрузки дополняют записи; пользовательские статусы сохраняются. ЛПР без контактов также переносятся; исходные строки получают отметку после подтверждённой записи человека.
6. Кнопка «Проверить новые контакты»: сохраняет правки, дополняет контактные вкладки, для файла компаний обрабатывает связанных ЛПР. Ранее проверенные контакты, включая невалидные, пропускаются.
7. Интеграция Promouser: email — услуга 17; подробный Telegram — услуга 6. Поля Telegram: ID_TG, Nickname_TG, Active_days_ago. Общий кеш и очередь защищают от повторных отправок и оплаты.
8. Единый таймер Apps Script примерно раз в пять минут для изменений непосредственно в Google Sheets. Установка требует разрешения владельца проекта.

Порядок работы пользователя описан в [WORKFLOW.md](WORKFLOW.md). Устройство приложения и ограничения — в [README.md](README.md).

## Текущее состояние подключения

Ключ Promouser сохранён в Script Properties; в исходниках его нет. Владелец согласовал автооплату до **5 USD за отдельный заказ**. Заказы дороже требуют подтверждения. Большая база может разбиваться на несколько заказов.

Живой запрос баланса вернул `PV_OWNER_AUTH_REQUIRED`: Google требует разрешение владельца на внешние запросы. Владельцу нужно один раз запустить `setupContactAutomation_` в редакторе Apps Script и подтвердить доступ. Это также устанавливает общий таймер. Оплаченные тестовые заказы не создавались.

На момент подготовки передачи идут заключительные проверки на отдельных синтетических файлах; до их уборки платная обработка отключена. Итоговый статус проверки и уборки должен быть уточнён перед новым живым тестом.

## Где менять код

- `src/Access.gs`, `Code.gs`, `Config.gs` — доступ, dispatcher и настройки.
- `PreparedData.gs`, `SourceRecords.gs` — распознавание и структура записей.
- `PreparedImport.gs`, `PreparedWorkbookImport.gs` — предпросмотр, подготовка и публикация исходной базы.
- `ContactSync.gs` — добавление новых контактов с сохранением истории.
- `SegmentRecords.gs`, `SegmentImports.gs`, `SegmentActions.gs` — нормализация, пополнение и перенос ЛПР.
- `Promouser.gs`, `ContactAutomation.gs` — валидация и фоновый обработчик.
- `Client.html`, `GridClient.html`, `GridPanel.html`, `GridStyles.html` — интерфейс.
- `tests/`, `scripts/check.mjs` — проверки; `.github/workflows/` — CI и публикация.

## Начало работы на другом компьютере

Откройте свежую копию репозитория в Codex. Установите Node.js 22 или новее и выполните:

```sh
npm ci
npm run check
npm test
```

Последний полный прогон: **647 тестов успешно**. Проверки интерфейса дополнительно находятся в `tests/browser/`.

Для обычной разработки и отправки изменений в GitHub не требуется переносить ключ Promouser или файл авторизации clasp на новый компьютер: действующая публикация использует GitHub Secret `CLASPRC_JSON`. Для ручной публикации смотрите `DEPLOYMENT.md`.

Новому сеансу Codex достаточно передать: «Прочитай AGENTS.md, HANDOFF.md и WORKFLOW.md. Продолжай разработку существующего приложения, сохраняя его инфраструктуру и данные».
