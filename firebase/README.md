# Закрытый указатель названий

В Firebase Spark проекта `outreach-directory` используется база Firestore `(default)`. Источником данных остаётся Google Диск. Пять записей за одну транзакцию обновляют два списка сегментов, каталог и две служебные записи. Поля каталога — ID и имя. У сегмента добавляются проект и раздел. Срок чтения каждого снимка — десять минут от начала сбора. Сервер планирует обновление каждые пять минут через существующий минутный обработчик Apps Script. При сбое клиент получает списки напрямую из Google. Расчётный объём при обычной работе — 1 440 записей Firestore в сутки. Квота чтений зависит от числа открытий.

## Доступ

Браузер получает право на чтение из действующего ключа закрытой ссылки с помощью HKDF-SHA256. Параметры — UTF-8 исходной строки ключа, соль `outreach-center/firebase-directory/v1`, имя проекта в качестве info, результат в base64url без дополнения. Для двух списков используется один HTTPS POST `documents:batchGet`. Право чтения передаётся в его теле. Перечисление коллекций закрыто. Открытие таблицы или карточки проходит отдельную проверку в Apps Script.

Владелец управляет документом `directoryAdmin/publisher` по IAM. Фоновый обработчик пользуется отдельным случайным правом записи. Его копия находится в личном JSON-файле владельца в корне «Моего диска». ID файла закреплён в `src/FirebaseDirectory.gs`. Перед записью проверяются привязка к корню, владелец, отсутствие общего доступа, родительская папка, версия конфигурации и действующий проверочный хеш ссылки. Чтение административных документов закрыто Rules. Лимиты одного поколения составляют 5 000 файлов, по 500 сегментов на проект и до 850 000 байт JSON на список.

## Операции владельца

Команды запускаются из корня репозитория с авторизованным профилем clasp владельца и правами на выделенный проект.

- `node scripts/firebase-directory.mjs status` — проверить проект, регион, включение публикации и ID приватной конфигурации.
- `node scripts/firebase-directory.mjs provision` — первоначальная настройка либо сверка ACL и установленных правил. Утилита принимает пустую базу с закрытыми правилами или точное совпадение с правилами приложения. При уже отключённой публикации повторная сверка сохраняет отключение.
- `node scripts/firebase-directory.mjs disable` — отключить выдачу и запись, убрать действующее поколение. Старая открытая вкладка могла уже получить имена до отзыва. Книги и содержимое Диска сохраняются.
- Для ротации сначала выполните `disable`, затем измените проверочный SHA-256 закрытой ссылки в Apps Script. Команда `node scripts/firebase-directory.mjs set-verifier <BASE64URL_SHA256>` принимает только готовый проверочный хеш. Затем выполните `node scripts/firebase-directory.mjs enable` и войдите по новой ссылке. До первого подтверждённого входа и прохода таймера используется обычный путь через Google. При ручном изменении только настройки Apps Script ранее выданный снимок остаётся доступен до истечения десяти минут.
- Если Google Диск использует иной корень или Apps Script использует переопределённый хеш, до первоначальной настройки задайте `FIREBASE_DIRECTORY_ROOT_ID` и `FIREBASE_DIRECTORY_VERIFIER`. Оригинал закрытой ссылки утилите не нужен.

Техническое состояние обработчика хранится в закрытом свойстве `FIREBASE_DIRECTORY_CLOCK_V1`. В нём есть время успешного обновления и этап ошибки либо HTTP-код. После истечения срока снимка следующий подтвержденный вход проверяет существование минутного таймера.

## Проверки

Модульные тесты публикации запускаются командой `node --test tests/firebase-directory.test.js`. Для проверки правил на чистом локальном эмуляторе запустите Firestore Emulator с `--project_id demo-directory --rules firebase/firestore.rules --host 127.0.0.1 --port 28563`. Задайте `FIRESTORE_EMULATOR_HOST=127.0.0.1:28563` и выполните `node firebase/test-rules.mjs`. В тесте используются случайные права только для этого процесса и пустые синтетические списки. [Модель доступа Firestore](https://firebase.google.com/docs/firestore/security/rules-conditions)
