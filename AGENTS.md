# Работа с проектом

Начинай с `HANDOFF.md`, `README.md` и `WORKFLOW.md`. Существующее приложение работает на Google Apps Script и Google Sheets; основной репозиторий — `seainkk/-`, ветка `main`.

## Изменения

- Работай с исходниками в `src/`. Сохраняй существующие проект Apps Script, deployment ID, URL и привязку к Google Диску.
- Сохраняй публичные входы `doGet`, `callApp`, `uploadSourceBase`. Обработчики бизнес-логики заканчиваются `_`; новые RPC включаются в явный dispatcher и проходят общую проверку доступа.
- Перед записью проверяй область доступа, реальные ID, принадлежность файлов папкам и ожидаемую версию данных.
- Сохраняй пользовательские колонки и статусы. Повторы импорта и неизвестный результат записи обрабатывай через прежний requestId и журнал операции.
- Контактные вкладки дополняются. Проверенные и вручную исключённые контакты сохраняют историю. Новый запуск валидации обрабатывает только контакты без завершённой проверки.
- Готовность исходника проверяется сервером во всех путях добавления в сегмент. ЛПР без контактов также сохраняются.

## Проверки и публикация

Используй `npm run check` и `npm test`. Для правок интерфейса запускай соответствующие проверки из `tests/browser/`.

Живые проверки выполняй только на собственных синтетических файлах; рабочие таблицы пользователя сохраняй. Синтетические контакты в Promouser не отправляй. Проверку подключения выполняй запросом баланса; платные операции покрывай моками.

Ключи API, закрытые ссылки с ключом и токены хранятся в закрытых настройках, а не в исходниках, логах и коммитах. Текущий согласованный лимит Promouser — 5 USD за отдельный рабочий заказ.

GitHub Actions публикует `main` в существующее развёртывание. Проверяй итог workflow и шаг обновления web app. При изменении OAuth scopes учитывай отдельное разрешение владельца Google; успешный deployment сам по себе его не выдаёт.

После существенного изменения обновляй `HANDOFF.md` и пользовательский порядок работы в `WORKFLOW.md`.
