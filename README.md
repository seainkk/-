# Реестр баз

Командное веб-приложение на Google Apps Script. Папки и рабочие данные находятся в Google Диске и Google Таблицах; исходный код и автоматическая публикация — в GitHub. Постоянно работающий компьютер или отдельный сервер не нужны.

## Вход по закрытой ссылке

Команда открывает постоянную страницу `https://seainkk.github.io/-/` с ключом после `#access_key=...`. Код этой страницы находится в `entry/`, публикация — workflow Deploy registry entry. Она загружает Apps Script в изолированном `credentialless` iframe: Google-cookies текущих аккаунтов не отправляются, в том числе вложенным окнам HTML Service. Это обходит ошибку маршрута `/u/1/` до запуска приложения. Поддерживаются актуальные Chrome и Edge; Firefox и Safari не поддерживают этот режим и получают явное сообщение, без загрузки обычного iframe с cookies.

Страница не содержит ключа в публичных файлах. Без правильного URL-фрагмента iframe не создаётся. Готовность показывается только после сообщения от успешно открывшегося Google-приложения; загрузка iframe сама по себе не считается успехом. Скопированная внутри сервиса ссылка ведёт на GitHub Pages. Для встраивания статический HTML Apps Script разрешает iframe через `ALLOWALL`; проверка ключа на каждом RPC остаётся обязательной.

Приложение выполняется от аккаунта, опубликовавшего его (`USER_DEPLOYING`), и разрешает открытие страницы без Google-входа (`ANYONE_ANONYMOUS`). Доступ к данным и действиям даёт случайный ключ в закрытой ссылке. Ролей и списка разрешённых Google-email в приложении больше нет.

Владельцу передаётся полная ссылка вида `https://seainkk.github.io/-/#access_key=КЛЮЧ`. Технический адрес Apps Script остаётся доступен для диагностики. Её можно переслать коллегам или скопировать кнопкой «Скопировать ссылку» внутри открытого сервиса. Все получатели имеют одинаковые рабочие возможности и могут переслать ссылку дальше. Обычный адрес `/exec` без ключа открывает только статический экран с просьбой получить закрытую ссылку.

Ключ состоит из 43 URL-safe символов и генерируется из 32 криптографически случайных байтов. В публичном коде хранится только его SHA-256 verifier; исходного ключа в репозитории нет. Не публикуйте полную ссылку в GitHub Issues, README, общедоступных документах или логах. В URL ключ находится после `#`, не в query-параметре; браузер получает его через `google.script.url.getLocation`. Клиент передаёт ключ в каждом серверном запросе по HTTPS, а сервер проверяет его до обращения к Диску. Значения ключа и OAuth-токенов не возвращаются в данных реестра и не журналируются приложением.

Google-права на файлы не меняются от выдачи ссылки сервиса. **Открытие и редактирование самих Google Таблиц требует прав на эти файлы.** Папка Диска не становится публичной. Действия внутри приложения выполняются с правами опубликовавшего аккаунта; индивидуального аудита сотрудников нет, новые служебные записи отмечаются общим актором `shared-link`.

## Реестр баз

В интерфейсе три раздела: **Реестр баз**, **Сегменты**, **Ретаргетинг**. Старого экрана дерева Диска нет. Физическая папка каталога по-прежнему называется «Исходные базы».

Каталог автоматически находит файлы из этой папки и её подпапок. У записи есть название, ссылка на файл, наполнение, статус обработки, ручная проверка формата и подтверждённые связи с сегментами. Для переноса листов в сегмент требуется настоящая Google Таблица.

Наполнение: «Компании», «ЛПР» или оба значения. В смешанной базе компании и ЛПР находятся на разных листах. Статус: «Сбор», «Готова», «Доработка». Ручная проверка: «Не проверено», «Корректно», «Некорректно». Критерий для компаний — одна строка соответствует компании; для ЛПР — одному человеку. Автоматическая проверка структуры пока не подключена. Изменение наполнения сбрасывает прежнюю проверку, если сотрудник явно не указал новый результат.

Поиск по названию не учитывает регистр и различие е/ё. Фильтры наполнения и «Без сегмента» комбинируются с поиском; смешанная база входит в обе категории. Неизвестные связи не считаются отсутствующими. Несохранённые карточки остаются видимыми с пояснением, даже если не подходят текущему фильтру. Есть счётчик найденных баз и сброс условий.

Отметки сохраняются по ID файла. Переименование не сбрасывает их; исчезнувшие из источника файлы архивируются в служебных данных, сохраняя историю. Одновременное сохранение устаревшей версии отклоняется. Каталог и аналитика обновляются вручную и раз в минуту, пока раздел виден; незавершённые формы и сохранения приостанавливают таймер. При закрытом приложении сканирования нет.

## Загрузка базы

Кнопка «Загрузить базу» предлагает название, наполнение и статус.

- **Файлом:** CSV, TSV, XLS, XLSX или ODS до 10 МиБ преобразуется в новую Google Таблицу в «Исходных базах». Файл на компьютере не меняется.
- **По ссылке, создать копию:** исходная Google Таблица должна уже находиться внутри реестра, кроме защищённой служебной таблицы. Реальное положение проверяется сервером.
- **По ссылке, перенести:** исходная Google Таблица должна находиться в «Исходных базах» или её подпапках. Перенос из сегмента не разрешён, чтобы не убирать его рабочий файл.

Таблицы вне реестра не импортируются по ID: в режиме владельца это дало бы получателю ссылки возможность действовать над посторонними файлами владельца. Такую базу сначала добавляет в нужную папку человек с соответствующими правами Google Диска, либо её загружают файлом. Проверки выполняются перед записью, восстановлением и повторным завершением операции. Режим копирования автоматически не подменяется переносом и наоборот.

Файл передаётся единственной HTML-формой `google.script.run` как Blob; в ней также находится проверяемый ключ доступа. Создание и перенос используют долговечные записи операций и приватные метки Диска. Подтверждённый результат не дублируется; неизвестный исход блокирует слепое повторение. При частичном сбое интерфейс сохраняет форму и ссылку на подтверждённый результат. Ошибки исходника, назначения, квот, политики и конкретного действия различаются без показа исходных ответов Google.

После подтверждения импорта отдельно запускается предварительный анализ состава Google Таблицы. Он считает найденные и уникальные email и телефоны, мобильные, компании с распознанными идентификаторами и контакты у нескольких компаний. Для существующей базы анализ можно запустить кнопкой «Проверить состав». Он читает только выбранный файл внутри «Исходных баз», не меняет ячейки, статусы или историю и не задерживает подтверждение импорта. Ошибка анализа не отменяет успешную загрузку.

Извлекаются только распознанные контактные столбцы; служебные адреса в комментариях и произвольных ячейках не собираются. Один адрес или номер считается один раз, а его связи с компаниями сохраняются. Повтор у нескольких разных компаний показывается для ручной проверки. Неопределённые владельцы, неоднозначные столбцы и неполное чтение отмечаются отдельно; частичный анализ не выдаётся за окончательный.

Для пилота подключён отдельный пустой «Кухни — Центр баз» в папке сегмента «Кухни» с тремя рабочими листами: «База», «Email», «Telegram». Анализ сравнивает состав исходника с этим файлом и отдельно показывает известные контакты, новые и новые без спорной принадлежности. Контакт у одной компании в исходнике и другой в Центре также попадает на ручную проверку. Неизвестная компания и несколько известных компаний различаются. ID компании локален для файла; объединение между файлами возможно по корректному ИНН или явному идентификатору происхождения. Название и домен сами по себе не доказывают совпадение.

Центр и его папка задаются `defaultContactCenterId` / `defaultContactCenterFolderId` либо приватными свойствами `CONTACT_CENTER_ID` / `CONTACT_CENTER_FOLDER_ID`. Перед чтением проверяются реальные положения обоих файлов в реестре, отдельная папка назначения и ожидаемые заголовки трёх листов. Произвольный внешний ID назначения от клиента не принимается. Неполный исходник, недоступный Центр или неоднозначные сведения о компаниях дают неизвестный соответствующий итог, а не ложный ноль или обещание добавить всё.

Перенос отдельных контактов пока не выполняется: это предварительный расчёт. Отчёт не означает, что контакты уже добавлены, провалидированы или готовы к рассылке. Анализ ничего не меняет в старых статусах и кампаниях; проверки через платные API и отправки не выполняются. Будущий перенос должен ещё раз проверить актуальное состояние и сохранить ID контактов и их историю.

## Сегменты

Каждая непосредственная подпапка «Аутричи» — отдельный сегмент. Они показаны строками с каналами, статусом, показателями и ссылками.

«Добавить сегмент» создаёт папку и две Google Таблицы: `Название: компании` и `Название: ЛПР`. Исходные базы необязательны — можно заполнить сегмент позже. «Редактировать сегмент» позволяет изменить название папки и назначенных файлов, добавить базы из реестра.

Загружать можно только базу с сохранённым статусом «Готова». Сервер повторно проверяет готовность, расположение и версию при просмотре листов и каждом добавлении. Сотрудник выбирает реальные листы, их назначение и наличие заголовка для каждого. Один лист идёт только в один файл; однокомпонентная база заполняет соответствующий файл.

Копируется весь выбранный лист. Исходник не изменяется, существующие рабочие листы не удаляются. Это снимок на момент загрузки, а не автоматическая синхронизация. Формулы копируются по обычным правилам Google, без собственного преобразования межлистовых ссылок. За действие допускается до пяти баз и двадцати листов. Подтверждённые копии и связи не дублируются. Если ответ `Sheet.copyTo` неизвестен, повтор блокируется до проверки результата по ссылке сегмента.

## Статусы и рассылки

- «Нет контактов» — проверенные листы пусты с учётом указанного заголовка.
- «Подготовка» — есть хотя бы одна строка данных.
- «В работе» предусмотрен для будущей проверки контактов со статусом «запущен».

Сервер читает наличие контактов ограниченными порциями; значения ячеек в браузер не передаются. Пустые отображаемые значения формул не считаются контактами. У старого листа с одной заполненной строкой и неизвестной настройкой заголовка статус остаётся неопределённым. Ошибка проверки не превращается в ложное отсутствие контактов.

Email, Telegram и Ретаргетинг по умолчанию красные; проверка запусков ещё не подключена. Показатели в работе пока показывают прочерки. «Рассылки» открывает экран Coldy/email и NSA/Telegram со списками, показателями отправлений, ответов и лидов и итогами. API пока не подключены; ручного ввода и вымышленных кампаний или нулей нет. Раздел «Ретаргетинг» ждёт согласования структуры.

## Служебные данные и границы

Служебная Google Таблица находится непосредственно в корне реестра. До чтения и записи проверяются ID, MIME и реальное положение, перед изменениями — права редактора. Используются листы `SourceBases` (13 столбцов, наполнение JSON в M), `SourceBaseSegments`, `SegmentTables`, `SegmentLoads`. Миграция прежних схем сохраняет отметки, версии и связи и выполняется под общей блокировкой.

Только `doGet`, `callApp` и форма `uploadSourceBase` являются публичными функциями. Бизнес-обработчики заканчиваются `_` и недоступны прямому `google.script.run`. Dispatcher содержит фиксированный список методов. Проверенный контекст существует только на время одного вызова и снимается в `finally`; подмена клиента или обход кнопки не заменяют ключ. Списки `ALLOWED_EMAILS` / `ADMIN_EMAILS` предыдущего режима больше не используются и автоматически не удаляются.

При необходимости владелец может заменить verifier свойством `SHARED_ACCESS_KEY_SHA256` в Script Properties. Значение — SHA-256 нового случайного ключа в Base64URL без `=`. Это отзывает старые ссылки, включая последующие запросы из открытых вкладок. Пустое или повреждённое свойство блокирует доступ. Без свойства используется verifier из `Config.gs`; исходный ключ не восстанавливается по хешу, поэтому полную ссылку нужно сохранить приватно.

Лимиты: до 5000 файлов каталога и 5000 строк на служебный лист. Проверка контактов ограничена 80 файлами, 240 листами, 100000 ячейками и 20 секундами на запрос; превышение отображается как неполная проверка. Квоты Google расходуются от аккаунта, опубликовавшего приложение.

## Отклик интерфейса

Форма сегмента использует уже загруженный каталог. При переходе между разделами успешные чтения повторно используются до 30 секунд; кнопка обновления запрашивает данные заново. Перед любым изменением сервер заново проверяет расположение файлов, готовность баз и их версии.

После подтверждения создания или импорта результат сразу появляется в списке, а полная проверка выполняется отдельно. Открытие форм и ввод не блокируются чтением списков; сетевые операции выполняются последовательно. Неизвестный результат записи сохраняет прежнюю защиту от повторного создания файлов и листов.

Журнал листов читается один раз на запрос списка сегментов. Между запросами серверный снимок не сохраняется. Создание Google Таблиц и копирование листов всё ещё требуют ответа Google и могут занимать время.

## Разработка и публикация

Подробности в [DEPLOYMENT.md](DEPLOYMENT.md). Проверки: `npm ci`, `npm run check`, `npm test`. Новых npm-зависимостей нет. Apps Script получает только `src/`.

Код в `main` проверяется и публикуется GitHub Actions → clasp. Прежний Deployment ID и базовый URL сохраняются. Скрипт дополнительно читает фактическую конфигурацию Google API и подтверждает анонимный доступ и выполнение от владельца; зелёные unit-тесты сами по себе не подтверждают эти настройки.

Тесты подменяют Google API. Проверки интерфейса с управляемыми задержками: `python tests/browser/performance_client.py` и `python tests/browser/contact_preview_client.py` (требуются Playwright Python и Chromium, рабочие файлы не затрагиваются). Отдельная браузерная проверка после публикации нужна для реального анонимного входа с URL-фрагментом. Тестовые контакты в рабочие файлы не добавляются. В `extension/` остаётся отдельный прежний прототип; он не требуется приложению и не опубликован в Chrome Web Store.
