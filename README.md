# Реестр баз

Командное веб-приложение на Google Apps Script. Исходные файлы и сегменты хранятся на Google Диске, рабочие данные — в Google Таблицах, код и публикация — в GitHub. Постоянно работающий компьютер или отдельный сервер не нужны.

[Открыть приложение](https://script.google.com/macros/s/AKfycbxKxdFPQt4gGQAOrgyRUBNm1yQEhEyEeXTiPPZqYz2KsVEZNyD6gXrDRj78BhgybCv0WA/exec). Нужен разрешённый Google-аккаунт.

В интерфейсе три раздела: **Реестр баз**, **Сегменты**, **Ретаргетинг**. Прежний экран, повторявший дерево Google Диска, удалён. Название «Реестр баз» теперь относится к каталогу исходных баз; физическая папка на Диске по-прежнему называется «Исходные базы».

## Реестр баз

Каталог автоматически собирает файлы из папки «Исходные базы» и её подпапок. У записи есть название, ссылка на оригинал, наполнение, статус обработки, ручная проверка формата и записанные связи с сегментами. Файлы разных форматов можно открыть по ссылкам; для загрузки листов в сегмент нужна настоящая Google Таблица.

**Наполнение:** «Компании», «ЛПР» или оба значения. У смешанной базы компании и ЛПР должны находиться на разных листах. Наполнение сохраняется в служебной таблице; прежние значения «Общая» и «ЛПР» совместимы с новой схемой. «Общая» преобразуется в «Компании».

**Статус:** «Сбор», «Готова», «Доработка». **Проверка формата:** «Не проверено», «Корректно», «Некорректно». Сейчас это независимые ручные отметки, сохраняемые кнопкой «Сохранить». Для компаний одна строка соответствует компании; для ЛПР — человеку с его контактами. У смешанной базы это правило применяется к соответствующим листам. Автоматическая проверка структуры не подключена. Смена наполнения сбрасывает прежнюю отметку проверки, если сотрудник явно не указал новый результат.

Новая найденная на Диске база получает «Сбор» и «Не проверено». Переименование файла сохраняет его отметки: записи связываются по ID. Удалённые или перемещённые из источника файлы исчезают из каталога, но служебные записи сохраняются для восстановления по тому же ID. При одновременном редактировании через приложение устаревшая правка отклоняется.

## Загрузка исходной базы

Кнопка **«Загрузить базу»** открывает форму с названием, наполнением и статусом.

- **Файлом:** CSV, TSV, XLS, XLSX или ODS до 10 МиБ преобразуется в новую Google Таблицу в папке «Исходные базы». Файл на компьютере не изменяется.
- **По ссылке:** доступная Google Таблица копируется либо перемещается. Копирование включено по умолчанию. При переносе исходная таблица сохраняет ID и содержимое, но меняет папку и название. Перемещение требует соответствующих прав Google Диска: право редактировать ячейки само по себе не гарантирует возможность переместить файл. Перед записью проверяются доступные Google признаки прав исходника и папки назначения; окончательное разрешение операции принимает Google. Если перенос запрещён, можно явно выбрать «Создать копию», когда копирование разрешено. Автоматической замены переноса копированием нет.

Ссылка может вести на таблицу вне реестра: доступ проверяется от имени вошедшего сотрудника. Служебную таблицу использовать как исходную базу нельзя. Ссылки с resource key поддерживаются серверным обращением к фиксированным адресам Google Drive API; OAuth-токены не возвращаются в браузер.

Форма передаёт файл единственным аргументом `google.script.run` как Blob. Повтор того же запроса восстанавливает уже созданный результат по журналу и метке Google Диска. Если исход операции не подтверждён, интерфейс сохраняет файл, параметры и ссылку восстановления; второй файл автоматически не создаётся. При ошибке после подтверждённого создания ссылка остаётся доступной.

## Сегменты

Каждая непосредственная подпапка «Аутричи» — отдельный сегмент. На экране они представлены строками с каналами, общим статусом, показателями и действиями. Базы каталога не мешают проверке сегментов: метаданные сегментов читаются только из «Аутричи», а не из всего дерева реестра.

**«Добавить сегмент»** создаёт папку и две вложенные Google Таблицы:

- `Название сегмента: компании`;
- `Название сегмента: ЛПР`.

Выбор исходных баз необязателен: можно создать пустой сегмент и заполнить его позже. **«Редактировать сегмент»** позволяет изменить название папки и двух назначенных файлов, а также добавить готовые базы из реестра.

Для заполнения доступны только базы со статусом **«Готова»**. Это проверяется сервером заново при просмотре листов, создании сегмента и каждом добавлении данных. Снятие готовности, перемещение исходного файла или устаревшая версия записи блокируют загрузку. Флаг в интерфейсе не может обойти проверку.

При выборе базы показываются её реальные листы. Сотрудник выбирает листы и наличие строки заголовков для каждого. Для смешанной базы каждый выбранный лист явно относится к «Компаниям» или «ЛПР». Один лист нельзя одновременно направить в два файла. Однокомпонентная база может заполнить только соответствующий файл.

Копируется весь выбранный лист с его структурой; данные не сводятся в одну общую вкладку. Исходные листы не изменяются. Это копии на момент загрузки, а не автоматическая синхронизация: последующая правка исходника не обновляет сегмент. Применяются обычные правила Google для копирования листов, включая работу формул; отдельного преобразования межлистовых формул приложение не выполняет.

Подтверждённые листы не дублируются при повторе запроса. Связь базы с сегментом записывается после подтверждения всех листов, выбранных в действии. При неопределённом ответе `Sheet.copyTo` повторное копирование блокируется: нужно проверить результат по ссылке на сегмент. Уже существующие рабочие листы и контакты не удаляются. За одно действие можно загрузить до пяти баз и двадцати листов; следующие можно добавить отдельным действием.

## Статусы и аналитика сегмента

- **«Нет контактов»** — все проверенные листы пусты, с учётом указанного заголовка.
- **«Подготовка»** — найдена хотя бы одна непустая строка данных.
- **«В работе»** предусмотрен для будущей проверки контактов со статусом «запущен».

Чтение наличия контактов ограничено папкой сегмента и выполняется на сервере; значения ячеек в интерфейс не передаются. Пустое отображаемое значение формулы не считается контактом. Неопределённая проверка или недоступная таблица не подменяются отсутствием контактов.

У новых загруженных листов настройка заголовка известна. У старого листа, где заполнена только первая строка и настройка отсутствует, невозможно отличить заголовок от одного контакта: показывается предупреждение и неопределённый статус. Физически пустые листы считаются пустыми; подтверждённая строка данных позволяет показать «Подготовка» даже при неполной проверке остальных файлов.

Email, Telegram и Ретаргетинг по умолчанию красные: проверка запуска пока не подключена. Будущий подтверждённый запуск включает зелёный индикатор. Показатели контактов и компаний в работе пока показывают прочерки, а не вымышленные нули.

Ссылка **«Рассылки»** открывает аналитику выбранного сегмента: Coldy для email и NSA для Telegram. Подготовлены список рассылок каждого сервиса, показатели «Отправлено», «Ответы», «Интересы / лиды» и суммы по сервису и сегменту. API ещё не подключены; ручного ввода, тестовых рассылок и придуманных показателей в рабочем интерфейсе нет. Неподключённый сервис отличается от подключённого сервиса с нулём рассылок.

Раздел **«Ретаргетинг»** пока содержит только сообщение, что структура обсуждается.

## Служебное хранилище

Служебная Google Таблица находится непосредственно в папке реестра. Приложение проверяет её ID, MIME и положение до обращения к ячейкам; изменение требует прав редактора. Недоступное хранилище не заменяется новым пустым файлом.

Листы:

- `SourceBases` — метаданные, ручные отметки, версия записи и наполнение (`contents` как JSON-массив). Колонка `baseType` сохраняется для совместимости; каноническое наполнение хранится в добавленной колонке M.
- `SourceBaseSegments` — подтверждённые связи исходных баз с сегментами.
- `SegmentTables` — назначение двух вложенных файлов каждому сегменту.
- `SegmentLoads` — выбранные исходные листы, файлы назначения, ID копий, настройка заголовка и стадия загрузки.

Прежняя схема из 11 или 12 столбцов обновляется автоматически под блокировкой без сброса статусов, версий и связей. Новые служебные листы сегментов создаются при первом действии с сегментом. Частичная миграция имеет журнал восстановления; неизвестная или повреждённая структура не перезаписывается.

Каталог и сегменты обновляются при открытии, вручную и раз в минуту, пока соответствующий раздел видим. Незавершённая форма и выполняемое сохранение приостанавливают автоматическое обновление. При закрытом приложении фонового сканирования нет.

## Доступ, настройка и публикация

Следуйте [DEPLOYMENT.md](DEPLOYMENT.md). До заполнения `ALLOWED_EMAILS` приложение закрыто. В Script Properties задаются `ROOT_FOLDER_ID`, `ALLOWED_EMAILS` и `ADMIN_EMAILS`; адреса вводятся через запятую без кавычек. Участникам отдельно выдаются права на папку и файлы Диска. `ADMIN_EMAILS` пока не образует полноценную ролевую модель.

Необязательные привязки: `SOURCE_BASES_FOLDER_ID`, `SOURCE_BASES_STORAGE_ID`, `SEGMENTS_FOLDER_ID`. Источники должны принадлежать реестру, сегменты — быть непосредственными подпапками «Аутричи», служебная таблица — находиться непосредственно в корне. Файлы назначения сервер определяет сам; клиент не передаёт произвольные адреса для записи.

Операции выполняются от имени вошедшего пользователя (`USER_ACCESSING`). OAuth-разрешения Drive/Sheets шире одной папки; ограничения команды, принадлежности файлов, готовности базы и назначения листов обеспечивает сервер. Advanced Drive API v3 нужен для преобразования и атомарного создания файлов. Для стандартного Cloud-проекта его включают отдельно; для автоматически созданного проекта Apps Script — автоматически при подключении сервиса.

Изменения в `main` проходят проверки и публикуются через существующий GitHub Actions → clasp. Секрет `CLASPRC_JSON` хранится только в GitHub Secrets. Существующий Deployment ID сохраняет URL. Пользователям нужно обновить открытые страницы. При изменении разрешений Google может запросить повторное согласие.

## Разработка и границы

```sh
npm ci
npm run check
npm test
```

Apps Script загружает только `src/`. Основные модули: `SourceBases.gs` — каталог и служебные данные; `SourceImport.gs` — импорт; `Segments.gs` — метаданные папок; `SegmentActions.gs` — создание, редактирование и копирование листов; `SegmentAnalytics.gs` — наличие контактов и экран рассылок; `Client.html` — интерфейс. Новых npm-зависимостей для этих функций нет.

Автоматические проверки используют подменённые Google API; браузерные проверки — макеты сервера. Они не подтверждают реальные права конкретного сотрудника или включение API в его Cloud-проекте. После публикации нужно проверить загрузку, создание сегмента и копирование листов под разрешённым Google-аккаунтом. Тестовые контакты в рабочие файлы не добавляются.

Ограничения: каталог до 5000 файлов и до 5000 строк на служебный лист. Проверка наличия контактов за один запрос ограничена 80 файлами, 240 листами, 100000 ячейками и 20 секундами; превышение показывает неполную проверку, не ложный пустой сегмент. Журнал операций хранит до 80 записей, не удаляя неподтверждённые действия для нового импорта.

В `extension/` остаётся отдельный прежний прототип браузерного меню. Он не нужен веб-приложению и не опубликован в Chrome Web Store. Подготовка фонового GitHub-исполнителя бэклога в эту версию не входит.
