# Реестр баз

Закрытое командное приложение на Google Apps Script. Базы — настоящие Google Таблицы в выбранной папке Google Диска; интерфейс и функции обновляются через GitHub.

[Открыть приложение](https://script.google.com/macros/s/AKfycbxKxdFPQt4gGQAOrgyRUBNm1yQEhEyEeXTiPPZqYz2KsVEZNyD6gXrDRj78BhgybCv0WA/exec) — потребуется вход в разрешённый Google-аккаунт.

В первой версии:

- дерево папок и таблиц с раскрытием и сворачиванием меню;
- создание папок и пустых баз в реестре, переименование баз;
- просмотр содержимого папок: подпапки и ссылки на базы;
- открытие каждой базы в новой вкладке Google Таблиц для обычной работы с данными;
- раздел «Сегменты» по подпапкам «Аутричи», с индикаторами каналов и блоком аналитики;
- раздел «Исходные базы» с файлами всех форматов, ручными статусами и сохранением отметок в служебной таблице;
- загрузка исходной базы файлом с преобразованием в Google Таблицу, а также копирование или перенос таблицы по ссылке;
- серверная проверка списка сотрудников и принадлежности файлов папке реестра.

Встроенного редактора таблиц нет. Добавление строк, изменение ячеек, формулы и совместная работа выполняются в самих Google Таблицах. Приложение не читает ячейки существующих рабочих баз: импорт, преобразование и копирование выполняет Google Диск. Перенос и переименование оригинала выполняются только при выборе соответствующего режима. Метаданные хранятся отдельно в служебной Google Таблице.

## Исходные базы

Раздел собирает файлы из папки «Исходные базы» и её подпапок. Поддерживаются Google Таблицы, CSV, Excel и другие файлы: ссылки сохраняют исходные названия и реальные форматы. Для Google Таблицы показывается её тип, а не вымышленное расширение `.xlsx`.

У базы есть два независимых поля: статус «Сбор», «Готова» или «Доработка» и результат проверки структуры «Не проверено», «Корректно» или «Некорректно». Сейчас это ручные отметки; автоматическое правило проверки «одна строка — одна компания» ещё не задано. Новые файлы получают «Сбор» и «Не проверено»; приложение не делает вывода о качестве их содержимого.

Кнопка «Загрузить базу» открывает форму с названием, типом «Общая» или «ЛПР» и статусом. Файл CSV, TSV, XLS, XLSX или ODS размером до 10 МиБ преобразуется в новую Google Таблицу непосредственно в папке исходных баз. Исходный файл на компьютере не изменяется.

По ссылке принимается Google Таблица, доступная вошедшему сотруднику, в том числе вне папки реестра. Режим по умолчанию создаёт копию; оригинал остаётся на месте. Режим «Перенести исходную таблицу» сохраняет ID и содержимое оригинала, но меняет его папку и название. Доступ к перемещению определяет Google Диск. Служебную таблицу нельзя использовать как источник импорта.

Тип базы хранится в поле `baseType` служебного листа `SourceBases`: `general` — общая, `lpr` — ЛПР. У ранее зарегистрированных баз тип по умолчанию «Общая». Новая колонка добавляется при первом обращении к разделу новой версией приложения; прежние статусы, версии и связи сохраняются. Для общей базы критерий проверки — одна строка на компанию; для ЛПР — одна строка на человека с контактами одного человека. Сам результат пока отмечается вручную. При смене типа прежняя отметка проверки сбрасывается в «Не проверено», если сотрудник явно не указал новый результат.

Повтор одного запроса загрузки не создаёт вторую таблицу: приложение сохраняет идентификатор операции и восстанавливает результат после неопределённого ответа Google. Если файл уже создан, а сохранение метаданных не подтверждено, интерфейс сохраняет выбранные параметры и ссылку на результат для восстановления. Это не автоматический запуск рассылок или загрузка в сегмент.

Служебная таблица создана в папке реестра. Лист `SourceBases` хранит метаданные и отметки по ID файла, `SourceBaseSegments` — связи с сегментами. Переименование файла не создаёт новую базу и не сбрасывает отметки. Удалённые или перемещённые из источника файлы исчезают из раздела, но служебные записи сохраняются для восстановления по тому же ID.

Приложение автоматически синхронизирует список при открытии раздела и при его обновлении; пока раздел видим, он обновляется раз в минуту. Фонового сканирования при закрытом приложении нет. Ручные изменения записываются кнопкой «Сохранить» и доступны команде после обновления, а не только в браузере одного сотрудника. При одновременном редактировании через приложение устаревшая правка отклоняется. Список ограничен 5000 файлами, а служебное хранилище — 5000 записями на лист; превышение отображается как ошибка, без скрытого усечения списка.

Список сегментов у базы отражает только записанные связи. Сам алгоритм загрузки базы в сегмент ещё не подключён; кнопка «Добавить в сегмент» пока неактивна. Нажатие не записывает фиктивную связь и не перемещает файлы.

При недоступной служебной таблице исходные файлы остаются видимыми, а изменение отметок отключается. Приложение не подменяет недоступную связь сообщением, что база никуда не загружена. Реестр и раздел сегментов работают независимо от этой таблицы.

Свойства `SOURCE_BASES_FOLDER_ID` и `SOURCE_BASES_STORAGE_ID` позволяют администратору переопределить привязки. Источник должен находиться внутри текущего реестра, а служебная Google Таблица — непосредственно в его корне. Приложение проверяет это перед чтением или записью служебных ячеек и никогда не создаёт новую служебную таблицу автоматически при ошибке доступа.

## Сегменты

Каждая непосредственная подпапка «Аутричи» — один сегмент. Вложенные папки не создают дополнительные сегменты: их таблицы относятся к родительскому сегменту. Файлы непосредственно в «Аутричи» в список сегментов не попадают. Карточка позволяет открыть папку сегмента и исходные Google Таблицы.

В карточке предусмотрены три индикатора: Email, Telegram и Ретаргетинг. Ниже находятся четыре показателя: контакты в работе по каждому каналу и уникальные компании, у которых запущен хотя бы один канал. Внизу располагается один общий статус: «В работе», «Подготовка» или «Нет контактов».

Правила определения запуска, подсчёта контактов и идентификации уникальной компании ещё не согласованы. Поэтому текущая версия показывает нейтральные индикаторы, прочерки вместо чисел и неопределённый общий статус. Прочерк не означает ноль. Наличие листа с названием канала само по себе не считается запуском рассылки. В карточках нет ручных переключателей статусов и кнопок запуска кампаний.

Данные раздела перечитываются при открытии, вручную кнопкой обновления и раз в минуту, пока раздел видим. Подсчёт по содержимому таблиц будет подключён после согласования правил; текущая версия читает только структуру папок и метаданные файлов.

Привязка по умолчанию указывает на существующую папку «Аутричи» внутри реестра. При необходимости администратор может задать её ID свойством `SEGMENTS_FOLDER_ID` в Script Properties. Папка обязательно должна входить в текущий реестр: указание чужого ID не расширяет доступ. Отсутствующая или неоднозначная папка источника отображается отдельным сообщением, а реестр продолжает работать.

## Первый запуск

Следуйте [инструкции подключения и публикации](DEPLOYMENT.md). Google Apps Script API включается владельцем один раз. Для первой загрузки кода требуется отдельная Google-авторизация через `clasp`; подключение Google Диска к чату её не заменяет.

До заполнения `ALLOWED_EMAILS` приложение закрыто для всех. Первичная настройка выполняется через **Project Settings → Script properties**, без запуска функций. Разрешённые адреса и административные настройки хранятся в Script Properties, а не в репозитории. Сотрудникам также нужны права на общую папку Диска.

В **Project Settings → Script properties** адреса указываются через запятую, без кавычек, например:

```text
ALLOWED_EMAILS = owner@example.com, member@example.com
ADMIN_EMAILS = owner@example.com
```

При первой настройке замените примеры своим Google-email и сохраните его в обоих свойствах. Добавьте `ROOT_FOLDER_ID` со значением `1WKcvDDKqYBo94eXsYc5vKp6OPtOzv6Wh`. Служебная функция `setupRegistry_` остаётся внутренним помощником; для запуска приложения выбирать её в редакторе не требуется.

## Обновления

Проверки запускаются для изменений в репозитории. Публикация из `main` включается после добавления Google-авторизации в секрет `CLASPRC_JSON`; ID существующего развёртывания уже задан в workflow. Новая версия переключает это же развёртывание, сохраняя адрес приложения. Открытые страницы получают новый интерфейс после обновления.

## Разработка

```sh
npm ci
npm run check
npm test
```

Исходники приложения находятся в `src/`, проверки и сценарии публикации — отдельно. `.clasp.json` содержит идентификатор проекта, но не данные авторизации.

## Меню задач внутри Google Таблиц

В [extension/](extension/README.md) находится отдельное расширение Chrome: раскрывающееся меню слева с кнопками «Провалидировать email» и «Распределить контакты», а также ссылкой на это приложение. Обе кнопки пока неактивны; расширение не читает и не меняет данные таблиц.

После установки меню появляется во всех обычных Google Таблицах, открываемых в этом браузере, включая файлы вне реестра. Установка нужна каждому сотруднику. Доступ к самому реестру и файлам по-прежнему определяется настройками приложения и Google Диска. В Chrome Web Store расширение пока не опубликовано.

Веб-приложение обновляется через текущую публикацию GitHub → Apps Script. Код установленного расширения обновляется отдельно: у этой версии — заменой локальной папки и перезагрузкой расширения; в дальнейшем можно подключить распространение через Chrome Web Store. В `clasp push` попадают только файлы из `src/`.

## Границы первой версии

Дерево ограничено 500 папками и таблицами вместе и 10 уровнями вложенности. Создание защищено от повторения последних 80 запросов. Отдельная ролевая модель пока не реализована: фактические ограничения операций задаются списком `ALLOWED_EMAILS` и правами Google Диска.

Приложение запрашивает разрешения Google для работы с Диском и Таблицами. OAuth-разрешения шире одной папки; ограничения реестра и команды дополнительно проверяет сервер приложения перед каждой операцией.

Для импорта подключён Advanced Drive API v3. Дополнительное разрешение `script.external_request` используется только для запросов к фиксированным адресам Google Drive API при работе со ссылками с resource key; пользовательские внешние адреса не запрашиваются, OAuth-токен не передаётся в браузер. После изменения разрешений Google может запросить повторное согласие. Настройка API описана в [DEPLOYMENT.md](DEPLOYMENT.md).

Автоматические проверки используют подменённые Google-сервисы. После развёртывания проверьте вход владельца и сотрудника, создание базы в нужной папке и открытие её ссылки в Google Таблицах. Расширение дополнительно нужно проверить после установки в обычный Chrome.
